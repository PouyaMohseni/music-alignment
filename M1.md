# M1 — Monotonic cross-modal alignment (the "new path")

Reformulate score-following from per-frame heatmap segmentation (Henkel /
CB_TA / all B-series) into **differentiable monotonic sequence alignment**:
audio-frame × score-onset-column alignment matrix, forward-sum monotonic-path
supervision, beta-binomial prior bootstrap, monotonic-Viterbi decode. Targets
the confirmed #1 error mode (repeat-ambiguity, task #24) that a per-frame
classifier structurally cannot resolve.

## Locked design decisions (don't re-derive)
- **Columns = onset anchors** (ordered unique onset frames), NOT uniform spatial
  columns. Makes the path stay-or-advance-by-one + surjective (== validated
  `extensions/alignment/forward_sum.py`), and matches how eval measures error
  (at onset times).
- **Base = D1** (`mymodel/d1_align_matrix/`): reuse its MERT AudioTower + CNN/
  transformer ScoreTower verbatim (strip-format, self-consistent, NOT the
  strip-vs-native-page-contaminated path). M1 delta = gather score-column embeds
  at onset anchors + swap objective (dense-CE+soft-DTW → forward-sum + prior) +
  swap decode (DTW → monotonic Viterbi).
- Similarity `A@Bᵀ/τ` IS the alignment matrix (single-head cross-attn scoring);
  multi-head/learned-proj is a Phase-2 ablation, not needed to prove the method.
- Repeats: align to the **unrolled** score (`extensions/alignment/repeat_unroll.py`)
  so the path is monotone in both axes; fold back to printed strip for readout.

## First real Phase-2 result + diagnosis (2026-07-26, job 66103830)

**63.3% pct@0.5s** on full MSMD test (mean 4.37s, med 0.30s), early-stopped
epoch 25, best val_frame_acc only 0.359. Well below B1a (88.9%), but M1's
first-ever full run vs B1a's many-day matured trajectory -- not apples-to-
apples yet. Diagnosed two specific causes, both from real measurement, not
guessing:

1. **Verified ground truth uses the SAME `kind='previous'` step-function
   convention as B1a/CB_TA** (`mymodel/d1_align_matrix/data.py`) -- eval only
   checks correctness AT onset instants, so "M1 needs sub-onset interpolation"
   was the WRONG framing initially considered. The real issue: Viterbi snaps
   HARD to one of N discrete onset columns, so a wrong pick costs a full
   inter-onset-gap error. Measured real gaps directly from noteheads.npz:
   median 0.174s, mean 0.244s -- same order of magnitude as M1's 0.300s median
   error, consistent with "picked the adjacent onset" as the dominant failure.
   B1a's continuous per-pixel heatmap doesn't have this all-or-nothing
   penalty structure.
2. Early stopping (patience=5) triggered at epoch 25 with best val_frame_acc
   only 0.359 -- clearly premature (~119s/epoch, cheap to be more patient).

**Applied (commit 3aae704), zero-retrain fixes tested on the EXISTING
checkpoint via `eval_m1_fixes_cpu.sh`:**
- `soft_position_readout` (mymodel/m1_monotonic/eval.py): blend onset_x over
  a local +/-window around the hard Viterbi pick, weighted by the alignment
  matrix's own local softmax -- graceful degradation instead of all-or-
  nothing on adjacent-onset confusion.
- `_ambiguity_mask`: replaces the geometric `_repeat_mask` (miscalibrated:
  11/15632 tagged) with a percentile-based top1-vs-top2 posterior-margin tag
  -- idea from Hentschel et al. "Time to Align!" (TISMIR, tismir.296, NOT a
  score-following paper -- a data-model/provenance paper, but its theme of
  alignment claims carrying explicit certainty maps directly onto M1's own
  posterior). Self-diagnosing repeat detector from the model's own output.

**Deferred (bigger, separate lifts, not done this pass):**
- Densify alignment target with interpolated virtual anchors between onsets
  (alternative/complement to the soft-readout fix, more invasive -- needs
  retraining, revisit if soft-readout alone isn't enough).
- Stronger visual backbone via DINOv2 tiled tokens (proven elsewhere in this
  project) instead of D1's shallow 3-block CNN -- MuSViT already tried and
  failed its own overfit bar (0.65 vs 0.90), see musvit_tower.py section above.
- "Breaks" (hard section-boundary constraint on the monotone path) from the

- Typed coordinate/timeline discipline (also from the paper) -- hygiene,
  would reduce the coordinate-mismatch bug class that's bitten this project
  repeatedly (strip-vs-native-page, the MuSViT column-remapping headache) --
  lower priority than the above.
